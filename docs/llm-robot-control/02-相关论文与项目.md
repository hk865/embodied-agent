# 相关论文与项目

核查日期：2026-09-15。正式论文结构化条目统一维护在项目 data/papers.csv；本页按当前研究问题导航。工程评测单列，不伪装成论文。

## 1. 优先阅读

| 工作 | 研究内容 | 对本专题的价值 | 本次阅读范围 |
|---|---|---|---|
| [Code as Policies](https://code-as-policies.github.io/)（2022） | 语言模型生成调用感知与控制 API 的程序 | “模型写程序操控机器人”的方法起点 | 官方项目页 |
| [VoxPoser](https://voxposer.github.io/)（2023） | 生成与观测对齐的 3D 价值图，再由规划器生成轨迹 | 研究模型空间推理与几何执行的分工 | 官方项目页 |
| [Inner Monologue](https://arxiv.org/abs/2207.05608)（2022） | 将环境和执行反馈写回规划过程 | 开环与反馈闭环的概念对照 | 本轮沿用前次官方摘要核查 |
| [Harness VLA](https://arxiv.org/html/2607.08448v4)（2026） | Agent 编排解析原语和冻结 VLA | 比较位姿工具与专用接触策略 | 前次已核查正文核心段落 |
| [Act-Observe-Rewrite](https://arxiv.org/abs/2603.04466)（2026） | 根据视觉观测与回合结果，在试验间重新生成控制程序 | 研究无梯度更新的试错与程序修正 | 本次核对官方摘要，全文待读 |

Code as Policies 说明程序可表达反馈循环和空间计算；VoxPoser 将语言条件映射为用于规划的空间目标。它们适合作为“模型输出什么、底层完成什么”的两种设计参考。[Code as Policies](https://code-as-policies.github.io/)、[VoxPoser](https://voxposer.github.io/)

Act-Observe-Rewrite 的摘要报告在三个 robosuite 操作任务中评估迭代控制程序生成。此处只记录方法线索，不引用未核对的成功率；无梯度更新仍可能有多轮环境试验成本。[论文摘要](https://arxiv.org/abs/2603.04466)

## 2. 工程评测入口

- [Astra 机械臂评测](https://openai.robocurve.org/gpt-6-astra/)：位姿工具驱动的真实机器人案例，详见本目录案例卡。
- [StationeryBench 评测](https://openai.robocurve.org/stationerybench/)：通用模型与 VLA 的系统对照，协议不完全一致。
- [Inspect Robots](https://github.com/robocurve/inspect-robots)：追踪评测框架、机器人适配和运行日志。
- [RPent](https://github.com/RLinf/RPent)：与原有 Agent + VLA 工程路线对接。

## 3. 每篇精读时回答的问题

1. 模型能看到图像、深度、对象坐标、接触信息中的哪些？是否有特权状态？
2. 模型输出技能、位姿、轨迹、控制程序还是关节动作？
3. API 隐含了多少定位、抓取规划和自动恢复能力？
4. 修改 prompt、程序、记忆或模型权重，各发生在何时？
5. 试错次数、人工复位、在线交互和推理成本是否计入预算？
6. 作者给的是最好演示、平均进度、完整成功率还是留出任务结果？

建议阅读顺序：Code as Policies → Astra 案例协议及轨迹 → VoxPoser → Act-Observe-Rewrite → Harness VLA。
