# 云服务器部署与远程操作准备

核查日期：2026-10-06。用户尚未租服务器，先准备通用 SSH 方案；候选为 AutoDL、阿里云和 Colab。目标是在云端运行 OpenVLA、π0.5、LIBERO、Harness VLA 和后续 πRL，本地 Codex 负责修改代码、发起实验、查询状态、诊断错误和回收结果。仿真优先，真机后定；SmoothRL 仍按“官方开源且有适用对照证据优于 πRL”作为替换条件。

当前完成的是部署方案与本地工具准备。没有租赁、连接或验收任何云服务器，没有安装云端依赖、下载模型权重或运行 GPU 实验。源码版本及实验协议沿用[已有 VLA 准备](VLA复现与仿真准备.md)与[版本锁](../../workspace/vla_baselines/sources.lock.json)。

## 推荐的运行方式

```text
本地 Codex / 编辑器
    │ OpenSSH：命令、rsync：代码与结果、SSH tunnel：Dashboard
    ▼
云端持久工作目录
    ├── 隔离的 OpenVLA / openpi / LIBERO / RPent / πRL 环境
    ├── 仿真与策略服务；同机或分 GPU，通过上游 endpoint 连接
    └── tmux 或平台作业：持续运行、日志、退出码、checkpoints
```

当前本地终端已能调用 `ssh`、`rsync` 和 `scp`。配置可用的 SSH 主机别名后，Codex 可以经终端在远端执行命令，并同步修改后的代码与实验产物；不要求云端另装 Codex，也不要求先安装插件。OpenSSH 已提供远程命令、跳板连接和端口转发。[OpenSSH 手册](https://man.openbsd.org/ssh.1)

仿真与策略尽量都在云机，避免每一步将图像从本地发到云端。openpi 已有 WebSocket policy server；RPent 已有 env、VLA、SAM3 服务 endpoint，可以分 GPU 或机器部署。第一版使用这些接口，后续按实测延迟和显存决定拆分。[openpi 远程推理](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/docs/remote_inference.md)、[RPent 服务部署](https://rpent.readthedocs.io/en/latest/rst_source/guides/advanced_deployment.html)

## Colab、AutoDL 与阿里云

这是基于当前官方文档与本项目需求的选型判断；没有核查账户库存、实时报价、购买资格或下载实测。

| 平台 | 当前适合的用途 | 对部署方式的影响 |
|---|---|---|
| Colab 托管 Notebook | 短时加载、推理与少量闭环验证 | GPU型号和运行时长动态变化；免费运行时不能按SSH服务器规划 |
| AutoDL 常规容器 | 优先尝试24 GB单卡基线，随后按峰值扩容 | 官方支持SSH；在容器内直接用uv/conda，不支持Docker套娃 |
| 阿里云 GPU ECS | 长期远程开发、持久服务、容器环境与多卡候选 | 标准SSH，可配置Docker及持久云盘；需核对地域、GPU直通规格和网络 |

**Colab** 免费托管运行时且无正计算额度时，官方禁止SSH/远程桌面、主要绕过Notebook的Web控制及分布式worker。付费并保持正计算额度可以移除这些额外限制，但仍不保证GPU型号和资源。一般最多12小时，Pro+有足够额度时连续执行最多24小时；运行时可能因闲置或生命周期结束被删除。第一版因此把Colab用于Notebook短验证，正式持续仿真/训练使用SSH主机。[Google FAQ](https://research.google.com/colaboratory/faq.html)

**AutoDL** 常规实例是容器。GPU选择还决定CPU/RAM配比，不能只看显存；系统盘30 GB、数据盘 `${EXTERNAL_LOCAL_PATH}/autodl-tmp` 50 GB起可扩容，建议 `remote_root=${EXTERNAL_LOCAL_PATH}/embodied-agent`，并把环境、缓存和模型放在数据盘。普通停机通常保留数据，连续关机15天会释放；重要checkpoint仍需定期回收。Pro使用网络系统盘、当前没有独立数据盘，连续关机60天释放；弹性部署停止后立即释放，不能混用保留规则。[环境与磁盘](https://www.autodl.com/docs/env/)、[SSH](https://api.autodl.com/docs/ssh/)、[常规保留规则](https://www.autodl.com/docs/instance_data/)、[Pro](https://www.autodl.com/docs/instance_pro/)、[弹性部署](https://www.autodl.com/docs/elastic_deploy/)

AutoDL学术加速支持部分GitHub/HF访问，不能据此保证openpi的GCS权重下载。开机后检查GitHub、Hugging Face和Google Cloud Storage链路；替换checkpoint时保留来源与协议差异。[网络说明](https://www.autodl.com/docs/network_turbo/)

**阿里云** 官方GPU计算型规格包含A10 24 GB（gn7i）、L20 48 GB（gn8is）及80/96 GB级实例；部分规格有地域限制。先选完整GPU计算型并验证EGL；不要将小显存vGPU分片当作整卡。ECS普通停机与释放不同；支持的节省停机模式可能回收计算资源，云盘仍计费，重启还受库存影响。云盘是否随实例释放需明确设置。[GPU规格](https://help.aliyun.com/zh/ecs/user-guide/gpu-accelerated-compute-optimized-and-vgpu-accelerated-instance-families-1)、[SSH](https://help.aliyun.com/zh/ecs/user-guide/connect-to-a-linux-instance-by-using-an-ssh-key-pair)、[Docker](https://help.aliyun.com/zh/ecs/user-guide/install-and-use-docker)、[停止实例](https://help.aliyun.com/zh/ecs/user-guide/stop-an-instance)、[云盘释放](https://help.aliyun.com/zh/ecs/user-guide/release-a-disk/)

某些计算GPU/驱动不提供需要的图形能力，阿里官方特别指出A30不支持图形加速。无论平台与显存大小，MuJoCo EGL都要实测；不能用`nvidia-smi`通过替代渲染验收。[GPU驱动指引](https://help.aliyun.com/zh/egs/installation-guideline-for-nvidia-drivers)

## 通用 SSH 工具

入口为 [cloudctl.py](../../scripts/cloud/cloudctl.py)，配置与用法见[云端工作区说明](../../workspace/vla_baselines/cloud/README.md)。SSH主机别名、身份与端口由用户的OpenSSH配置管理；项目JSON只保存别名、远端工作目录与Python解释器。

从项目根运行下面的命令可查看计划，不连接服务器、不建立隧道，也不修改远端：

```bash
python3 scripts/cloud/cloudctl.py push
python3 scripts/cloud/cloudctl.py doctor
python3 scripts/cloud/cloudctl.py exec -- nvidia-smi
python3 scripts/cloud/cloudctl.py job-status --id pi05-smoke
python3 scripts/cloud/cloudctl.py job-logs --id pi05-smoke --lines 100
python3 scripts/cloud/cloudctl.py pull workspace/vla_baselines/artifacts
python3 scripts/cloud/cloudctl.py tunnel --local-port 8000 --remote-port 8000
```

租赁后复制example为 `config.local.json`，填SSH别名和持久盘路径，核验主机指纹并准备无交互认证，然后在子命令前加入 `--config … --execute`。`push`同步代码，排除凭据、源码快照、权重、数据、环境与运行产物，不删除远端文件；固定源码由云端运行已有bootstrap脚本取得。`pull`回收选定的相对路径；大checkpoint按需单独选择。

`job-start`将命令交给云机tmux中的 [remote_job.py](../../scripts/cloud/remote_job.py)，`job-status/logs/stop`管理该作业。需要云机有Python 3.10+、tmux与rsync；本地不必有tmux。作业记录在远端项目的 `.cloud/jobs/<id>/`，保存命令、合并日志、状态和退出码；每次运行使用新id。SSH工具本身不是执行沙箱，显式运行的命令拥有SSH用户权限。

Dashboard、Rerun/Web viewer与策略端口通过绑定本机 `127.0.0.1` 的隧道访问；服务器端服务也优先仅监听localhost。隧道命令需要持续运行，关闭隧道只会断开访问。长期训练通过作业托管，不能靠维持一个前台SSH连接。

## 按实验阶段选资源

下表的“规划候选”是本项目的建议，尚未在租赁机器验证。官方显存估计受模型、精度、batch、并发环境与实现路径影响；多张卡不会自动合并成一张卡的显存。

| 阶段 | 官方证据 | 规划候选 |
|---|---|---|
| π0.5 推理与 LIBERO 闭环 | openpi 总体估计推理 >8 GB | 先 1×24 GB，16–32 vCPU、64–128 GB RAM、300–500 GB 持久盘 |
| OpenVLA 原精度推理 | 7B 模型；官方评测在 A100 | 1×24 GB 起测；量化另作对照 |
| Harness：π0.5、SAM3、仿真 | RPent 没有全栈最低显存承诺 | 1×48 GB 或 2×24 GB，后者分别放 VLA 和 SAM3；先测各服务峰值 |
| π0.5 LoRA | openpi 总体估计 >22.5 GB | 1×32–48 GB 较有余量；确认所选 JAX/PyTorch 路径支持需要的功能 |
| OpenVLA LoRA | 官方约27 GB 下限，示例 A100 80 GB | 1×48/80 GB，并按 batch 实测 |
| π0.5 全参 SFT | openpi 总体估计 >70 GB | 1×80 GB 起测，不能据此保证任意 batch |
| πRL 论文复现 | 论文用 8×H100 80 GB，RL 只训练约300M动作专家 | 正式预算按多卡安排；单卡80 GB只作为缩小配置排错的候选 |

[openpi 要求](https://github.com/Physical-Intelligence/openpi#requirements)、[OpenVLA LoRA](https://github.com/openvla/openvla#fine-tuning-openvla-via-lora)、[πRL Appendix B.2](https://arxiv.org/html/2510.25889v3#A2.SS2)

RLinf 的减负 quickstart 在4×H100上有官方比较，但固定源码的该文件默认是 **π0**。这不能当作 π0.5 已在4卡或单卡复现的证据。我们保存的 π0.5 配置使用 `train_expert_only=True`，默认 `no_shard`，不能自动汇总多卡显存；该 openpi 路径也不能随意打开 gradient checkpointing。先减环境并发、micro batch 或按上游支持使用 offload，再检查 global batch 整除和完整训练状态。[RLinf 官方说明](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/pi0.html)、[固定 π0.5 配置](https://github.com/RLinf/RLinf/blob/c70606f08cdca259b8dec03d4430926b5b8fac9d/examples/embodiment/config/libero_spatial_ppo_openpi_pi05.yaml)

π0.5 公开模型约3.3B，BF16纯参数大小的理论估计约6.6 GB；实际运行还包含其他精度参数、激活与临时张量。我们的16 GB本机值得先测单模型推理，但推理、微调和强化学习是不同资源需求。先租24 GB做闭环验证，再依据测得的峰值扩容，可以避免一开始就租多卡训练机器。

## 环境、磁盘与渲染

优先 Ubuntu 22.04 x86_64 与上游已验证的 CUDA/框架版本。云机选择24 GB消费卡时仍需核对 GPU 架构；原版 OpenVLA 的 Torch 2.2 等旧依赖不能直接假定支持最新显卡。本地5070 Ti的兼容性结论也不能直接套到 A100/H100。

保留原版 OpenVLA、官方 openpi server、LIBERO client、RPent 与 πRL 的独立环境。RPent 使用的 RLinf/openpi 分支与 πRL 当前 main 分开锁定。记录 commit、依赖锁、容器 digest（若使用）、权重 revision/逐文件 hash、归一化统计、相机预处理与动作接口。

推荐让 `remote_root` 位于停机保留的盘上，并在工作区内分开保存：

```text
workspace/vla_baselines/
    repos/          # 固定版本源码，云机按锁下载
    .venvs/         # 独立环境，或平台 conda 环境
    cache/          # OPENPI_DATA_HOME、HF_HOME 等
    checkpoints/    # 权重、训练 checkpoint 与优化器状态
    datasets/       # 真正需要训练时再下载
    artifacts/      # 体检、配置、指标、失败视频、作业状态
```

可用 Docker 时，先验证 NVIDIA Container Toolkit 与匹配官方镜像；RLinf 的示例使用20 GB共享内存。GPU渲染还需 graphics 能力，仅通过 CUDA tensor 测试不代表 EGL 可用。平台给的是容器且不支持 Docker 时，使用平台驱动与隔离的 uv/conda 环境；不要在租赁容器内再启动 Docker daemon。[NVIDIA 安装](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)、[容器 GPU 能力](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/docker-specialized.html#driver-capabilities)、[RLinf 安装](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/pi0.html#installation)

LIBERO 无桌面渲染先设置 `MUJOCO_GL=egl`、`PYOPENGL_PLATFORM=egl`。先不加载模型，验证 reset、RGB 与深度图；EGL失败再评估OSMesa并记录CPU开销。JAX 默认会预分配显存，同卡跑 SAM3 与仿真时先测 `XLA_PYTHON_CLIENT_PREALLOCATE=false`，必要时分GPU。[JAX 显存说明](https://docs.jax.dev/en/latest/gpu_memory_allocation.html)

## 插件是否必要

第一版不需要插件：本地 Codex 的终端调用 SSH，文件走 rsync，长期实验走云端 tmux/平台队列。模型计算使用云端 GPU，本地只承担编辑、运维与结果展示。

插件目录中可检索到 **Remote Desktop Commander**，描述提供远端文件与终端操作；当前未安装或连接。只有需要连接器方式、且其认证与服务器环境匹配时再评估。检索到 **DigitalOcean** 也不代表它支持我们的 AutoDL/阿里云账户或提供合适的 GPU；当前不引入服务商专用插件。

若以后需要在没有本地 SSH 客户端的产品里调用远端工具，可以把已验证的操作封装成 MCP，再按 OpenAI 插件规范打包。MCP只封装操作，不代替 GPU 运行环境、身份认证与训练保活。OpenAI 另有 Agents API 的 self-hosted executor，需要独立 API 集成与受限环境密钥；它不等于当前聊天已自动获得某台云服务器访问权。[插件打包](https://developers.openai.com/plugins/build/plugins)、[API 自托管执行环境](https://developers.openai.com/api/docs/guides/agents-api/environments/self-hosted)

## DSH 备选核查

本机核查源码为 `${USER_HOME}/projects/deepseek-harness/deepseek-harness-master`，CLI版本 `0.1.7-rc.1`。正式入口是 **DeepSeek Harness 的 `dsh`**。此源码、当前 PATH 与插件目录没有发现名为 `dshtui` 的可用程序；若用户另有该程序，需根据其实际接口再接入。

| 现有接口 | 可用于本项目的部分 | 限制 |
|---|---|---|
| `dsh --profile headless "任务"` | 通过 SSH 委托一次明确的智能排错任务 | 由另一个智能体执行提示词，不是直接 shell RPC |
| Python / TypeScript SDK | stdio JSON-RPC 提示词与会话事件 | 实装只有 initialize、session/prompt、shutdown；没有直接 exec/get_file/取消 turn API |
| Web Remote API | session prompt/page/follow、取消；job list/follow/kill | 属于Web应用RPC，需配套客户端与认证 |
| Web `/api/file?path=…` | 小日志、图像和报告 | 通常20 MiB上限；全量返回，不支持Range，不适合权重与大数据 |
| dsh-ssh / fs-ssh / subprocess-ssh | 远端文件、进程、PTY | 需要匹配Node/helper与hash；断线/租约到期清理进程，没有自动恢复 |

证据位置：`apps/cli/README.md:9–28`、`packages/sdk/server/src/server.ts:248–257`、`packages/api/session-controller/src/index.ts:407`、`packages/api/job-controller/src/index.ts:75`、`packages/api/session-controller/src/media-references.ts:66`、`packages/ssh/ssh/README.md:28–61`。

DSH 的本地 jobs 状态在内存中，Harness退出就不再托管；SSH helper也不是训练调度器。若启用此备选，采用 **云端 dsh headless/SDK 做一次排错 → 标准 SSH/rsync 回收文件**，训练仍由 tmux/平台作业托管。Web交互通过SSH tunnel；本机版本默认监听 `127.0.0.1:3080`，CLI拒绝 `--host 0.0.0.0`；认证是launch token换signed cookie，不是bearer-token通用API。

## 到手后的验收顺序

1. 确认 SSH 别名、工作目录所在的持久盘、GPU型号/显存、RAM/CPU、剩余盘、驱动、外网下载与端口转发。运行体检只算盘点完成。
2. 同步代码；云端按锁准备源码，再分别安装隔离环境、锁定全部依赖。模型与训练数据在云端下载，验证hash，不从本机盲目全量上传。
3. 做 CUDA 运算和无模型 LIBERO reset/RGB/深度渲染，确认 EGL 与坐标/深度单位。
4. 加载匹配权重，验证合成输入与动作维度；再跑固定 `libero_spatial`、seed=7、每任务1回合的10回合开发测试。记录峰值显存、推理延迟与完整退出状态。
5. Harness先验证官方单任务，再加入Planner/memory。RPent指定的checkpoint与官方openpi GCS checkpoint分开记录，不能静默代换。
6. 小规模训练先检查 loss/reward、实际更新参数、checkpoint保存与恢复。通过后才扩到正式 πRL 预算。

长期作业保留 stdout/stderr、配置、seed、代码与权重身份、成功谓词、失败视频和退出码。tmux能承受SSH断开，但不能承受关机、容器释放或进程被杀；训练恢复依赖保存在持久盘的完整 checkpoint。后续单独验证恢复逻辑，不能仅凭文件存在就宣称可续训。

服务器租好后所需输入为：可用 SSH 主机别名、持久工作目录、GPU与磁盘信息、先跑哪一阶段。私钥和密码保存在用户本机 SSH 配置/agent，不写进仓库或聊天。当前不需要提供这些输入，先完成通用准备。
