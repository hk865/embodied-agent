# TurboVLA

> **论文**：[TurboVLA: Real-Time Vision-Language-Action Model at 32 Hz on an RTX 4090 with <1 GB VRAM](https://arxiv.org/abs/2607.27205)  
> **版本 / venue**：arXiv:2607.27205v2，2026-08-16 更新（预印本）  
> **项目 / 代码**：[github.com/H-EmbodVis/TurboVLA](https://github.com/H-EmbodVis/TurboVLA)  
> **证据**：⚠️ 作者自评（本文档为首版卡片，仅基于摘要与 arXiv 元数据，正文细节待核）  
> **本库定位**：消费级显卡（RTX 4090 上 0.9 GB 显存、约 32 Hz）可常驻的实时 VLA 后端候选，直接关系到 B0 冻结 VLA 与延迟感知模式在本地 16 GB 硬件上的可行性

## 一句话

把常规 LLM 中心的 \(V \to L \to A\) 通路重构为直接的 \(V + L \to A\) 映射：视觉与语言各自独立编码，通过轻量双向视觉—语言交互交换信息，再由紧凑解码器直接输出连续 action chunk，从而降低每次策略调用的计算与显存开销。

## 问题与假设

- 论文认为现有 VLA 的 \(V \to L \to A\) 设计（把视觉投影进 LLM 表征空间）在每次策略调用时都产生大量计算与显存开销。
- 核心假设是"直接 \(V+L \to A\) 映射"能在不明显损失任务性能的前提下大幅降本——这是设计动机，具体证据强度需通读正文核验。
- 它研究的是**实时 / 低资源推理**问题，不是长程记忆、扰动或恢复。

## 对当前课题的作用

- 对应本地 baseline：B0（冻结 VLA 后端）候选；0.9 GB 显存意味着本地 16 GB 卡上可与其他模块（渲染、Agent）常驻共存，是延迟感知模式的重要匹配对象；
- 可以直接复现的变量：LIBERO 上的 checkpoint 成功率、端到端推理延迟与峰值显存；
- 只能做概念对照的部分：与更大 VLA 的跨论文绝对分数比较；
- 会改变哪个模块接口：暂无（作为标准 VLA 后端接入 Execution Adapter，动作合同待核）；
- 下一步实验：通读正文与代码，确认动作空间 / 相机 / 归一化能否对齐 LIBERO 任务，再决定是否作为 B0 主后端并与 SmolVLA 成对比较。
