# 面向冻结视觉—语言—动作模型的具身智能体执行框架：研究综述与开题方案

## 摘要

视觉—语言—动作模型（Vision-Language-Action Model，VLA）已经具备从视觉观测和语言指令生成机器人动作的能力，但其优势主要体现在有限时间范围内的感知—动作映射。在多阶段任务和分布扰动条件下，目标重绑定、局部误差累积、终止判断滞后和失败恢复不足仍会显著降低任务成功率。现有层级 VLA 和外部执行框架表明，高层任务分解、解析原语、执行验证与外部记忆可以改善上述问题；然而，规划器、工具分解、任务轨迹、失败规则和引导数据的贡献往往相互混杂，实时性与资源成本也缺少统一报告。

本课题拟在冻结 VLA 的条件下复现 RPent/Harness 执行框架，并研究两项轻量增量：类型化事件校验和结构化能力记忆。系统采用事件触发的高层智能体管理任务状态和工具调用，采用传统规划控制处理可解析的自由空间阶段，采用冻结 VLA 执行接触密集的局部操作。实验以公开检查点、LIBERO/LIBERO-Pro 和自生成仿真轨迹为主，比较直接 VLA、协议复现 Harness、事件校验和能力记忆，联合报告成功率、恢复率、失败发现延迟、冗余动作、推理时延和显存占用。本研究旨在界定低算力条件下 VLA 外部执行框架的有效范围，不涉及新 VLA 的预训练、完整生成式世界模型或在线强化学习。

**关键词：** 具身智能体；视觉—语言—动作模型；外部执行框架；结构化记忆；失败恢复

## 1. 绪论

### 1.1 研究背景与意义

VLA 将视觉观测、自然语言任务和机器人本体状态映射为关节或末端动作。与只输出文本或语义标签的视觉语言模型相比，VLA 直接参与物理闭环，因而能够利用大规模视觉语言预训练中的语义知识，同时学习抓取、放置、开合和插入等连续控制行为 [1–3]。

现有 VLA 通常一次生成单步动作或有限长度的动作块（action chunk）。动作块提高了推理效率和短时动作连续性，但单次输出只覆盖局部时间范围；模型也通常不显式保存跨阶段任务进度、失败类型和恢复历史。因此，局部技能可用并不等价于多阶段任务可靠。多阶段任务还要求系统维护目标对象、阶段顺序、完成条件、剩余预算和环境变化，并在局部执行失败后选择不同的恢复策略。

由此产生一个独立于 VLA 训练的问题：如何把冻结 VLA 作为有限能力的执行模块，置于一个能够管理外部状态、约束工具调用、验证执行结果并进行失败恢复的运行时中。该问题同时连接 VLA、具身智能体、机器人规划控制和系统评测，具有明确的工程价值和研究可验证性。

### 1.2 研究对象与范围

本研究的对象是**冻结 VLA 的外部执行框架（Harness）**，而不是新的端到端基础模型。研究范围如下。

| 维度 | 本研究范围 |
|---|---|
| 任务 | 仿真中的多阶段机器人操作及分布扰动 |
| VLA | 公开的任务检查点；推理时冻结参数 |
| 高层决策 | 事件触发的 LLM/VLM 智能体或固定状态机 |
| 外部能力 | 类型化原语、结构化状态、执行校验和失败记忆 |
| 数据 | 公开数据集、公开检查点和自生成仿真轨迹 |
| 计算资源 | RTX 5070 Ti 16 GB、64 GB 系统内存；必要时仅对少量最终实验租用服务器 |
| 不纳入范围 | VLA 预训练、π0.5 全量或 LoRA 微调、完整生成式世界模型、在线强化学习、真实机器人安全认证 |

课程要求中的感知、导航、操作和交互工具将在仿真演示中完成接口验证；论文式研究评测聚焦冻结 VLA 的操作执行框架。LIBERO 不包含移动导航，因此其结果不用于支持完整服务机器人或语义 SLAM 的能力声明。

### 1.3 研究问题

本课题围绕四个研究问题展开：

- **RQ1：执行框架收益。** 在 VLA 检查点、感知输入、原语库和执行预算相同的条件下，外部执行框架相对直接 VLA 是否提高分布扰动下的任务成功率和恢复率？
- **RQ2：事件校验收益。** 相对原 Harness 的终止谓词（stop predicate），类型化事件校验是否降低失败发现延迟和失败后的冗余动作数？
- **RQ3：能力记忆收益。** 在引导样本（bootstrap data）和检索预算相同的条件下，结构化能力记忆相对原始文本型 Global Memory 是否减少留出随机种子（held-out seeds）上的重复失败？
- **RQ4：资源约束下的净收益。** 将推理等待、动作过期和显存占用计入后，上述收益在单张 16 GB 显卡上是否仍然成立？

RQ1 首先检验 Harness 的整体收益；A0 再以固定状态机作为归因对照。若 LLM 规划器在相同工具、感知、预算和恢复规则下不优于固定状态机，则结果只能支持 Harness 的有效性，不能支持 LLM 规划器的必要性。

## 2. 相关研究

### 2.1 模型内部的层级推理

π0.5 [4] 在同一模型中先预测低频语义子任务，再基于该子任务生成低层动作块。其家庭场景量化评测中的许多任务约持续 2–5 分钟，论文同时报告了 10–15 分钟的整屋清理过程。该工作说明层级语义推理能够支持真实多阶段操作，但其能力依赖大规模异构数据、跨本体数据和专门后训练，不能直接外推到任意开源检查点。

OneTwoVLA [5] 将显式推理与动作生成统一在一个模型中，并在关键时刻切换到推理模式。该路线减少了高低层模型之间的能力错配，但仍需要推理中心数据合成和联合训练，训练与复现成本高于本课题允许的范围。

两项工作表明，长程能力可以在模型内部实现；同时也说明该能力并非由更长的语言上下文自然产生，而是来自层级推理接口、训练数据和执行闭环的共同设计。

### 2.2 外部智能体与工具化 VLA

Goal2Skill [6] 采用 VLM 高层规划器维护结构化任务记忆，执行目标分解、结果验证和错误修正，低层 VLA 负责局部动作。该工作支持“高层语义推理—低层动作执行”的双系统路线，但需要额外 VLM 规划器，并在特定 RMBench 协议下评测。

VLAs-as-Tools [7] 将多个专用 VLA 组织为工具族，通过显式工具选择和执行中进度反馈实现事件触发重规划。其 Tool-Aligned Post-Training 进一步提高调用一致性，但需要对 VLA 做工具对齐后训练，不属于纯冻结后端方案。

Harness VLA [9] 将冻结 VLA 暴露为接触操作原语，并与预对位、搬运、导航和释放等解析原语组合。其 Task Specific Memory 保存参考任务的原语结构，Global Memory 保存成功规则和失败模式。论文在标准 LIBERO 上将同一冻结检查点的成功率由 95.3% 提高到 96.0%，在 LIBERO-Pro 协议下由 50.0% 提高到 72.1%（Codex）或 82.4%（Claude Code）。这说明外部重绑定和原语编排在分布扰动下具有明显作用；标准任务上的小幅变化也表明，Harness 的价值主要出现在局部策略分布之外。

原 Harness 已包含短时段（burst）VLA 执行、终止谓词（stop predicate）、空抓取和误判成功规则。因此，本课题首先复现原有机制，再将“类型化事件校验”限定为相对原机制新增的信号、返回语义或检查频率，避免把已有能力重复表述为创新。

### 2.3 外部记忆、结果校验与恢复

HELM [8] 将情景记忆、学习式状态校验器和回滚重规划组合为外部 Harness。在其 LIBERO-LONG 协议中，系统成功率由 OpenVLA 的 58.4% 提高到 81.5%；仅把上下文窗口扩展到 $H=32$ 的增益为 5.4 个百分点。该结果支持“长程问题不等同于上下文长度”的判断，也表明记忆、校验和恢复需要分别评估。

Harness VLA 的 Goal-S 结果从不检索目标设置相关 Task Specific/Global Memory 时的 31.0% 提高到使用引导记忆时的 87.0%；Goal-T 的相应变化为 79.0% 到 87.0%。这是零样本与少样本整套记忆条件的比较，同时改变了任务轨迹、Global Memory 和引导信息，不能视为 Task Specific Memory 的单变量消融。

RMBench [13] 通过九类依赖历史观测的操作任务区分不同记忆复杂度，并提供可消融的显式记忆策略。该基准说明“是否需要历史信息”本身可以被操作化测量，但其重点是策略内部记忆，不直接回答外部执行框架应如何存储失败与技能工作域。

现有工作已表明外部记忆具有潜在价值，但仍存在两个与本课题直接相关的问题。其一，文本式 Global Memory 难以表示技能工作域、成功概率和不确定性；其二，记忆条件常伴随额外探索数据和执行预算，若不控制信息量，难以判断收益来自记忆结构还是额外经验。

### 2.4 传统规划控制、SLAM 与世界模型

相关模块解决的问题不同，不构成单一替代路线。

| 模块 | 主要问题 | 输出 | 在本课题中的位置 |
|---|---|---|---|
| 感知与状态估计 | 当前观测和机器人状态是什么 | 对象、位姿、置信度、时间戳 | 持续运行的状态服务 |
| SLAM | 移动机器人在哪里，地图是什么 | 位姿、地图及其不确定性 | 仅在移动/跨区域任务中加入 |
| 高层智能体 | 当前应执行哪个子目标和工具 | 类型化原语调用 | 事件触发的控制平面 |
| 传统规划器 | 如何在显式约束下到达目标状态 | 路径、轨迹或不可行结果 | 自由空间、预对位、搬运和导航 |
| VLA | 当前局部场景中如何行动 | 单步动作或动作块 | 接触密集的局部执行 |
| 世界模型 | 给定动作后状态如何变化 | 动作条件后继状态或观测 | 可选的后果预测模块 |
| 运动控制与安全层 | 如何跟踪参考轨迹并约束执行 | 关节命令、限幅和停止 | 高频公共基础设施 |

SLAM 估计当前状态和地图 [16]；世界模型预测动作条件下的未来 [17]；规划器求解可行路径或轨迹；控制器执行参考轨迹（reference）。结果分类器若只预测成功或失败，应称为执行结果校验器或结果预测器（outcome predictor），而不是完整世界模型。完整世界模型可以辅助候选排序或规划，但不会自然取代状态估计、碰撞约束和高频控制。

上述模块可以通过类型化接口向高层智能体提供能力，但“可被调用”不等于“由 LLM 按需启动”。状态估计、移动任务中的 SLAM、运动控制和公共安全层应持续运行；高层智能体只调用其任务级操作或读取结构化结果。世界模型在特定工作域内可以替代规划器使用的部分动力学近似或候选评分器，不能据此推导传统规划控制栈整体失去必要性。

### 2.5 研究现状小结

| 路线 | 代表工作 | 高层机制 | 低层执行 | 主要证据 | 与本课题的关系 |
|---|---|---|---|---|---|
| 模型内层级 | π0.5、OneTwoVLA [4,5] | 语义子任务或自适应推理 | 同一 VLA | 真实多阶段任务 | 能力强，但依赖联合训练和大规模数据 |
| 双系统规划 | Goal2Skill [6] | 外部 VLM 规划、记忆和反思 | VLA 子任务执行 | RMBench [13] | 支持高低层分工，额外模型成本较高 |
| VLA 工具族 | VLAs-as-Tools [7] | 工具选择与事件重规划 | 专用 VLA 工具 | LIBERO-Long、RoboTwin 2.0 [15] | 需要工具对齐后训练 |
| 记忆与校验 | HELM [8] | Harness Controller | VLA + 学习式校验器 | LIBERO-LONG、CALVIN [12] | 支持记忆—校验—恢复分解，增加学习组件 |
| 冻结 Harness | Harness VLA [9] | 高层智能体 + 固定原语 + 两类记忆 | 冻结 VLA | LIBERO-Pro [11]、RoboCasa365 [14]、RoboTwin 2.0 [15] | 最符合本课题资源约束，但归因和实时性仍需补充 |

截至目前，相关证据仍存在四项缺口：

1. Harness 增益可能同时来自工具分解、LLM 规划、引导轨迹和失败规则，组件贡献尚未充分隔离；
2. 原终止谓词的信号和检查粒度依任务实现而异，类型化失败传播及动作块内监督仍缺少统一比较；
3. 文本 Global Memory 缺少可校准的技能工作域表示；
4. 单卡条件下的成功率、延迟、动作过期和显存占用尚未形成统一评测。

上述缺口构成本课题的方法与实验依据。2026 年相关工作多为 arXiv 预印本，其结果应按各自协议理解，不宜跨基准直接比较绝对成功率。

## 3. 问题定义与研究假设

### 3.1 VLA 动作接口

对连续动作 VLA，一次推理可表示为：

$$
A_t=[a_t,a_{t+1},\ldots,a_{t+H-1}]\in\mathbb{R}^{H\times D},
$$

其中 $H$ 为动作块长度，$D$ 为具体本体的动作维度。动作坐标系、绝对或增量表示、归一化方式和执行步数均由检查点与机器人接口决定，不存在适用于所有 VLA 的统一 $H$ 或 $D$。

π0/π0.5 的公开 openpi 路径支持流匹配（flow matching）连续动作头 [19]；原始 OpenVLA 通过离散动作 token 再反量化 [2]。无论内部表示如何，外部执行框架接收的都应是具有明确控制语义的动作或动作块，而不是视觉 latent。VLA_ACT 是 Harness 人工定义的工具接口，也不是从模型隐状态自动析出的原语。

动作块内部通常近似开环，块边界重新观测后形成滚动闭环。场景图、任务进度和失败历史属于外部执行状态；除非检查点经过相应训练，否则不作为 VLA 的直接输入。

### 3.2 长程任务的操作化定义

长程任务不仅由物理时间决定。本文采用以下任务尺度向量：

$$
\mathcal{H}=
(N_{\mathrm{subgoal}},
N_{\mathrm{primitive}},
N_{\mathrm{contact}},
T_{\mathrm{episode}},
N_{\mathrm{recovery}}),
$$

分别表示必要子目标数、必要原语数、接触阶段数、回合（episode）持续时间和恢复事件数。实验中的任务跨度分组应依据任务定义或专家最短结构预先登记，而不是使用方法实际调用的原语数；后者会受到失败和重试影响，属于结果变量。

常见任务尺度可分为三类：

| 尺度 | 代表任务 | 适合检验的能力 |
|---|---|---|
| 局部技能 | 单次抓取、插入、开合 | 局部感知—动作映射 |
| 多阶段桌面操作 | LIBERO [10]、LIBERO-Pro [11] | 阶段组合、目标重绑定和分布扰动 |
| 长程移动操作 | π0.5 家庭任务 [4]、RoboCasa365 [14] | 多对象顺序、移动预对位和长时间误差累积 |

LIBERO-Pro 主要是分布扰动基准，不应单独作为任务跨度扩展（horizon scaling）的证据。若要支持长程结论，需额外采用 LIBERO-LONG、CALVIN [12]、其他公开长程任务或按预注册结构组成多阶段任务。

若每个必要阶段的成功概率近似为 $p$，在独立假设下，$n$ 个阶段串联的成功概率为 $p^n$。该关系只用于说明局部误差随阶段累积的趋势，不作为真实系统的独立性假设。

图 2 表达的是研究假设而非确定因果。具体检查点可能包含历史观测、滚动重规划或一定恢复能力，因而各条路径均需通过错误标注、任务跨度分组和组件消融进行检验。

外部智能体可以管理任务结构和工具生命周期，但其作用存在明确边界：

| 外部智能体可以承担 | 外部智能体不能替代 |
|---|---|
| 子目标分解、目标绑定和工具选择 | 毫米级接触控制与高频轨迹跟踪 |
| 任务进度、预算和完成条件管理 | 位姿估计、地图构建和传感器同步 |
| 失败事件解释和恢复策略选择 | 关节限位、碰撞监控和急停 |
| 外部记忆检索和同类失败规避 | 冻结 VLA 原本不具备的局部技能 |
| 目标变化后的重新规划 | 未经训练获得动作条件未来预测 |

因此，本课题检验的是外部执行框架能否改善系统级组合与恢复，而不是预设智能体能够解决全部长程问题。

### 3.4 外部信息需求与不确定性约束

运行时信息按时效与用途分为五类：

1. **观测与状态信念（belief）：** 图像、本体状态、对象位姿、置信度和时间戳；
2. **任务状态：** 当前子目标、对象绑定、已完成阶段、预算和最近失败；
3. **情景轨迹：** 原语调用、执行证据、结果和恢复过程；
4. **能力记忆：** 特定技能在对象、相对预对位和观测条件下的成功统计；
5. **知识检索：** 操作手册、技能说明和历史案例。

强时效状态必须以带版本的结构化数据维护。知识检索可以采用 RAG，但向量库不承担当前位姿、任务进度和实时对象状态的存储职责。

外部记忆首先是一种状态与数据管理机制，并不等同于扩大 LLM/VLM 的对话上下文。固定状态机、关系数据库或事件日志均可维护任务进度和失败历史；LLM/VLM 的可选作用是解释非结构化指令、检索相关记录和选择任务级工具，而不是充当唯一存储介质。因此，“VLA 上下文较短”并不能直接推出“必须增加另一个大模型”。

LLM、VLA、学习式校验器和感知模型均为不确定组件。系统可靠性依赖对其输入、输出和控制权限进行约束：

| 组件 | 主要不确定性 | 允许的输出 | 管理方式 |
|---|---|---|---|
| 感知 | 误检、位姿误差、陈旧观测 | 带置信度、坐标系和时间戳的状态信念 | 最小置信度、坐标系检查、obs_id |
| LLM/VLM 智能体 | 非法调用、非确定决策、长尾延迟 | 白名单内的类型化原语及参数 | 接口模式（schema）校验、固定模型版本与温度参数、预算与日志 |
| VLA | 空抓取、停滞、动作偏置 | 有限预算的动作块 | 本体适配、终止谓词、事件校验和重新预对位 |
| 学习式校验器 | 失准与分布偏移 | 结果类别、概率和证据 | 阈值验证、Brier/ECE、规则后备 |
| 规划控制 | 不可行轨迹和跟踪误差 | 参考轨迹或明确不可行结果 | 约束检查、闭环跟踪和错误码 |
| 公共安全层 | 传感器和执行风险 | 限幅、停止和 UNSAFE 事件 | 高频独立运行，所有实验条件共用 |

高层智能体的作用不是消除这些不确定性，而是在统一契约下使用、记录和传播不确定性。

### 3.5 研究假设

在上述问题定义下，提出以下可检验假设：

| 假设 | 对应比较 | 预期结果 |
|---|---|---|
| H1：外部编排假设 | M1 相对 M0 | 在分布扰动任务中提高回合成功率和恢复率 |
| H2：类型化监督假设 | M2 相对 M1 | 在恢复策略不变时降低失败发现延迟和失败后的冗余动作数 |
| H3：能力记忆假设 | M3 相对等信息量文本记忆 | 在留出随机种子上降低同类失败重复率，并提高恢复率 |
| H4：资源净收益假设 | 延迟感知模式下的 M2/M3 相对 M1 | 在预注册的显存、p95 延迟和过期动作阈值内保持成功率增益 |

若相应统计比较不支持假设，则结论应收缩为组件无增益或仅在特定感知、任务与资源条件下有效。

## 4. 拟议方法

### 4.1 设计原则

拟议系统遵循四项原则：

1. **冻结局部策略。** VLA 参数在主实验中保持不变，系统收益归因于外部执行机制；
2. **事件触发决策。** 高层智能体只在任务或原语状态变化时调用，不参与高频控制；
3. **类型化执行契约。** 每个原语声明输入、坐标系、前置条件、预算、终止条件和标准结果；
4. **控制权分层。** 解析规划、VLA 动作、运动控制和安全层不同时写入同一层控制命令。

### 4.2 原语库与阶段控制

拟采用少量、固定的原语库。原语数量保持稳定，以避免把结果提升混同为人工增加技能。

| 物理阶段 | 执行模块 | 说明 |
|---|---|---|
| 自由空间与长距离运动 | IK/轨迹生成 + OSC、阻抗或 PID | 约束明确，采用解析规划—控制栈 |
| 预对位 | 解析原语 | 将局部状态恢复到 VLA 较熟悉的工作域 |
| 抓取、插入、开合等接触阶段 | 冻结 VLA_ACT | 利用学习策略处理复杂视觉和接触关系 |
| 搬运、释放与撤退 | 解析原语 | 目标明确，减少不必要的 VLA 调用 |
| 速度、关节、工作空间与紧急停止 | 公共安全层 | 对所有实验组保持一致，不作为消融变量 |

系统不采用监督 MPC 与 VLA 同时改写同一接触动作。下游 MPC 或其他控制器仍可在接口定义清楚时跟踪参考轨迹。

原语调用至少包含名称与版本、参数、坐标系（frame）、时间戳、obs_id、前置条件、动作或时间预算、终止条件和是否允许中断；返回结果至少包含状态码、执行证据、是否可恢复和新观测版本。具体接口模式见附录 A。

### 4.3 类型化事件校验与恢复

原 Harness 的 `vla_act` 已接受终止谓词，并在短时段动作执行之间检查终止条件。M1 复现该机制；M2 在此基础上研究统一的类型化执行结果：

$$
y_k\in
\{\text{SUCCESS},\text{CONTINUE},\text{EMPTY\_GRASP},
\text{STALLED},\text{TIMEOUT},\text{UNSAFE}\}.
$$

其中 UNSAFE 由公共安全层上报，不属于可消融的学习式校验能力。第一版校验器采用部署时可获得的低成本信号，包括夹爪宽度、末端位姿进展、目标跟踪、动作幅值和连续无进展步数。

主实验采用预注册的确定性恢复表，避免将校验收益与 LLM 自由规划混合。表中的“重试预算”是原语级预算 $B_r$；每次可恢复失败使 $B_r\leftarrow B_r-1$，当 $B_r=0$ 时返回不可恢复失败。

| 事件 | 执行器即时行为 | 固定恢复动作 | 预算变化 |
|---|---|---|---|
| SUCCESS | 丢弃剩余动作并结束当前原语 | 转入下一预注册原语 | 不消耗重试预算 |
| CONTINUE | 继续当前动作块 | 无 | 不变 |
| EMPTY_GRASP | 丢弃剩余动作、张开夹爪并撤退 | 重新观测；按固定顺序选择相邻预对位区间 | $B_r-1$ |
| STALLED | 丢弃剩余动作并撤回安全预对位 | 增大净空；若仍停滞则切换预注册解析原语 | $B_r-1$ |
| TIMEOUT | 终止当前原语 | 在剩余预算内切换备选原语，否则结束回合 | $B_r-1$ |
| UNSAFE | 公共安全层立即停止 | 记录安全事件；不由可消融校验器自动恢复 | 按统一安全协议处理 |

同一任务、事件和重试序号对应唯一恢复模板；模板参数在开发集上确定后冻结。LLM 可以接收事件用于后续任务分解，但在 M2 主实验中不得改写上述即时恢复规则。

校验机制分两步评估：

1. 在相同执行轨迹、观测信号和检查周期下离线比较原终止谓词与类型化结果，隔离检测能力；
2. 在不改变恢复策略的条件下，将检查移至动作块内部每 $k$ 步或低成本事件，测量失败发现延迟和冗余动作变化。

只有规则校验出现稳定误差上限时，才训练轻量结果预测器（outcome predictor）。该模型仍属于结果分类器；除非显式预测动作条件后继状态，否则不归类为世界模型。

### 4.4 结构化任务状态与能力记忆

本研究将运行时状态和持久记忆分开。该划分是面向本课题的操作性设计，不作为通用记忆分类法。

| 状态或记忆 | 主要内容 | 留出评测时更新 | 跨回合持久化 |
|---|---|---:|---:|
| 工作任务状态（Working Task State） | 当前目标、对象绑定、阶段、预算、obs_id | 是 | 否 |
| 单回合恢复历史（Episode Recovery History） | 本回合的失败、参数和恢复结果 | 是 | 否 |
| 引导任务轨迹（Bootstrap Task Trace） | seed 0 的相对原语结构与验证证据 | 否 | 是 |
| 文本型 Global Memory | 原 Harness 的成功规则和失败模式；M1 基线 | 否 | 是 |
| 类型化能力记忆（Typed Competence Memory） | 技能工作域、成功统计和失败分布；M3 替换项 | 否 | 是 |

原 Harness 的 Task Specific Memory 在本实现中对应引导任务轨迹，Global Memory 对应文本规则基线。M3 保持任务轨迹不变，以类型化能力记忆**替换**文本型 Global Memory；二者同时使用的加法条件仅作为 A1 消融。

引导任务轨迹不保存可直接复用的绝对位姿，而保存相对预对位、阶段顺序、前置条件和失败模式。能力记忆使用如下条件键：

$$
k=(\text{primitive},\text{object class},
\text{relative staging bin},\text{context bin}),
$$

其中，context bin 表示由可见性、感知置信度和任务阶段构成的离散上下文区间。其值保存成功/失败计数和失败代码分布。对条件 $k$ 使用 Beta-Bernoulli 平滑：

$$
p_k\mid s_k,f_k\sim
\operatorname{Beta}(\alpha+s_k,\beta+f_k),
\qquad \alpha=\beta=1.
$$

候选恢复参数由固定模板生成。检索先匹配完全相同的对象类别和任务阶段，再扩展到相邻预对位区间；候选分数定义为

$$
\operatorname{score}(k')=
Q_{0.05}\!\left[p_{k'}\right]-\lambda d(k,k'),
$$

其中 $Q_{0.05}$ 为成功概率后验的 5% 分位数，$d$ 为预注册的离散条件距离。若样本数不小于 $n_{\min}$ 且该分位数低于 $\tau_{\mathrm{disable}}$，则禁用该候选；其余候选按分数排序，并以固定配置编号打破并列。$\lambda$、$n_{\min}$ 和 $\tau_{\mathrm{disable}}$ 仅在开发集选择，随后冻结。当前 episode 在同一条件下出现同类失败时，禁止以相同参数重复执行该原语。

### 4.5 感知证据等级

目标绑定、预对位位姿和“目标是否随末端移动”均需有明确估计来源。实验采用两级感知条件：

| 条件 | 输入 | 用途 |
|---|---|---|
| P0：特权仿真状态（Oracle） | 仿真对象位姿和接触状态；基准成功谓词默认仅供评测器 | 隔离高层智能体、校验和记忆的因果贡献 |
| P1：最小非特权感知（Minimal） | RGB-D 几何、轻量检测/跟踪和本体感知 | 小规模部署性复核 |

若基准成功谓词在线暴露给高层智能体或校验器，则单列为特权在线监控（oracle-monitor）条件。所有主实验在同一感知等级下比较。

## 5. 实验方案

### 5.1 环境、模型与数据

标准 LIBERO [10] 用于验证直接 VLA 与 Harness 的基本可运行性；LIBERO-Pro [11] 的指令重定向、对象或位置交换用于分布扰动主实验。若形成长程结论，还需增加 LIBERO-LONG、CALVIN [12]、其他公开长程任务，或依据预注册最短结构构造多阶段组合，不能以 LIBERO-Pro 代替任务跨度基准。

VLA 后端优先采用与任务和动作接口模式匹配的公开 π0.5 检查点。当前仓库中的 SmolVLA 权重是基础模型和接口资产，不是可直接用于 LIBERO 闭环评测的策略检查点 [20]；只有获得匹配任务检查点或使用公开数据完成适配后，才用于闭环实验，其结果也不表述为 π0.5 Harness 复现。

规则校验器不需要训练。可选学习式校验器的数据主要来自自生成仿真轨迹，通过预对位偏移、遮挡、对象交换、动作块截断、摩擦变化、延迟和丢帧生成失败。训练、验证和测试按任务、回合和随机种子划分，避免相邻帧泄漏。

|---|---|---|
| M0 | Frozen VLA 直接执行 | 局部策略基线 |
| M1 | 固定 RPent commit、P0 条件下的协议复现 | 复现外部编排、原终止谓词和原记忆机制 |
| M2 | M1 + 类型化事件校验 | 评估失败语义和检查粒度 |
| M3 | M2 中以 Typed Competence Memory 等信息替换文本型 Global Memory | 评估结构化技能工作域 |
| A0 | 固定状态机 vs LLM 规划器 | 隔离 LLM 规划器的独立增量 |
| A1 | 无记忆、Task Trace、文本型 Global、类型化替换、类型化追加 | 隔离记忆组成与替换/追加效应 |
| A2 | 原终止谓词、同检查周期的类型化结果、动作块内事件 | 隔离结果语义与检查频率 |
| A3 | 规则、学习式替代模型、规则—学习集成模型 | 评估学习校验器的必要性 |

16 GB 单卡上的 M1 首先追求 RPent [18] 协议层一致：固定工具、终止谓词、记忆、预算和高层智能体语义，并让全部方法共享 P0 感知。只有检查点、感知栈、任务资产和规划器条件均与论文一致时，才称为全栈复现并比较论文绝对数字；否则只报告本地成对差值，不以论文绝对成功率作为复现判据。

### 5.3 公平性与评测隔离

所有主实验共享：

- 同一 VLA 检查点、动作适配和仿真资产；
- 同一感知等级、初态、环境随机种子和扰动；
- 同一原语库、成功谓词、公共安全层和执行预算；
- 同一功能模式或延迟感知模式；
- 固定的 LLM 供应方、模型版本、温度参数、系统提示和 token/重试预算。

M1 需要记录原终止谓词的输入、检查频率、触发时机、剩余动作处理和特权状态依赖。M2 的新增机制必须相对该基线逐项声明。

随机种子 0 或明确的引导数据划分只用于构造持久记忆，留出随机种子评测时冻结持久记忆并禁止写回。各记忆条件报告引导阶段所需的环境重置、环境步数、VLA 调用、高层智能体调用、墙钟时间、API token 和费用。

主分析在阶段 0 后、开发 M2 前完成预注册。默认任务集合为 RPent 所用 LIBERO-Goal 的全部 10 个任务，在位置交换（Goal-S）与指令重定向（Goal-T）两类扰动下分别使用 10 个留出随机种子；若固定代码版本的任务定义不同，则以其正式清单替换并在采集结果前冻结。主要终点为按任务宏平均的回合成功率，关键次要终点为恢复率和失败后冗余动作数。5 个百分点的成功率差异作为最低关注效应，统计推断同时报告置信区间。实验采用固定样本量，不根据中途效果提前停止；若资源不足，须在查看方法差异前统一缩减任务或随机种子，并记录变更。

### 5.4 评价指标与统计方法

指标按研究声明分组：

| 研究声明 | 主要指标 | 辅助指标 |
|---|---|---|
| 任务和长程改善 | 回合成功率；按预注册任务跨度分组的成功率 | 子目标完成率、目标绑定准确率 |
| 失败校验有效 | 失败发现延迟；失败后冗余动作/动作块 | 空抓取/停滞的精确率、召回率和 F1 |
| 恢复有效 | 恢复率 | 同类失败重复率、恢复调用数 |
| 能力记忆有效 | 留出随机种子成功率与重复失败率 | 检索命中、引导数据成本 |
| 高层智能体有效 | A0 中 LLM 相对 FSM 的成功率增益 | 决策延迟、非法调用、token 和费用 |
| 系统可运行 | 回合墙钟时间、VLA/高层智能体 p95、峰值显存 | 过期动作、截止时间违约、长期显存增长 |
| 学习校验有效 | AUROC/AUPRC、Brier、ECE | 相对规则的闭环增益 |

恢复率的分母必须由预先定义的可恢复扰动和特权恢复路径（oracle recovery path）确定，不能依据某方法是否成功恢复事后选择。

方法间使用配对随机种子。置信区间按任务聚类进行配对或层级自助法（bootstrap），避免把同一任务的多个回合视为完全独立样本。开发阶段使用 4 个代表任务 × 3 个随机种子排错；正式主分析使用第 5.3 节冻结的任务与样本量，并报告准确分母。

### 5.5 功能模式与延迟感知模式

两种运行模式分别报告：

1. **功能模式：** 仿真允许等待高层智能体/VLA，验证任务逻辑和组件归因；
2. **延迟感知模式：** 世界持续运行，动作可能过期，报告真实墙钟时间、过期动作和截止时间违约。

只有功能模式改善时，结论限定为执行逻辑有效；只有延迟感知模式仍保持净收益时，才支持实时系统价值。

## 6. 可行性分析

### 6.1 硬件与软件约束

当前实验设备为 RTX 5070 Ti 16 GB、Core Ultra 7 265KF 和 64 GB RAM。openpi 官方给出的单卡估计为：推理需要超过 8 GB，LoRA 微调需要超过 22.5 GB，全量微调需要超过 70 GB [19]。因此，π0.5 在本课题中仅用于冻结推理；与仿真和感知模型能否同时常驻仍需实测。

openpi 官方测试环境为 Ubuntu 22.04。当前 Windows 工作区需先验证 WSL2/Linux GPU、驱动和仿真渲染链路。若采用 JAX 后端，还需测量 XLA 预分配、warm-up 峰值和内存碎片。

LeRobot 硬件指南将 SmolVLA 训练的显存量级估计为约 10–16 GB（batch size 8，结果受图像分辨率和配置影响）[21]。本地 SmolVLA 基础模型可用于接口开发或轻量适配，但不能替代任务检查点。

### 6.2 阶段 0：系统可行性评估

在实现复杂高层智能体前，完成以下测量：

- 检查点加载、预热和首帧延迟；
- 单次 VLA 推理 p50/p95；
- 一个动作块的仿真执行时间；
- VLA、仿真和可选感知模型的峰值显存；
- 长回合的显存稳定性；
- 高层智能体/API、校验器和感知的独立墙钟时间；
- 功能模式与世界持续运行模式的差异。

阶段 0 的产物是固定的软件版本、资源配置和延迟基线，而不是成功率结果。

### 6.3 帧处理与模型驻留

摄像头帧采用“最新完整帧组”（latest-complete-bundle）策略：多相机图像只有在同一时间窗内完整到达时才组成观测，并记录最大时间偏差。VLA 不需要处理摄像头的每一帧；过期帧可丢弃，高频控制器继续执行当前缓存动作。

VLA 至少在一个回合或一批任务/随机种子内常驻 GPU。系统内存可存放数据集、检查点缓存、帧缓冲和日志，但不采用逐帧或逐动作块的 CPU—GPU 整模型换入换出。分进程可以改善故障隔离，不能降低总显存，额外 CUDA 上下文还可能增加占用。

若 π0.5 与环境无法在 16 GB 稳定共存，降级顺序为：

1. 移除非必要重型感知、降低渲染负担并检查内存预分配；
2. 使用与任务和动作接口模式匹配的小型公开检查点完成系统归因；
3. 在关键最终实验中短时租用更大显存；
4. 若仅有未适配的 SmolVLA 基础模型，则只完成接口与资源验证，不报告闭环策略结论。

## 7. 预期贡献、研究计划与风险

### 7.1 预期贡献

本课题拟形成三项可检验成果：

1. RPent/Harness 的可复现基线及类型化事件监督扩展；
2. 类型化事件校验与能力记忆的可归因实现及消融；
3. 面向单卡资源的功能—延迟双模式评测协议。

LangChain/LangGraph、VLA 工具封装、普通 RAG 和规则状态机属于实现手段，不单独作为研究创新。

### 7.2 研究计划

| 阶段 | 目标 | 主要产物 | 退出条件 |
|---|---|---|---|
| A：接口与测量 | 跑通冻结 VLA 和环境 | 动作适配、轨迹接口模式、资源报告 | 连续推理稳定 |
| B：协议复现 | 完成 M0/M1 | 固定基线、终止谓词与记忆审计 | 配对基线可重复 |
| C：事件校验 | 完成 M2/A2 | 类型化结果、检测与延迟报告 | 同检查周期与动作块内对照完成 |
| D：能力记忆 | 完成 M3/A1 | 只读持久记忆、引导数据成本 | 留出评测完成 |
| E：部署性复核 | 完成 P1 和延迟感知模式 | 非特权感知与墙钟时间结果 | 能力边界明确 |

可选学习式校验器仅在规则校验存在稳定误差上限后进入阶段 E。

### 7.3 风险与证伪条件

| 结果 | 研究解释 | 后续处理 |
|---|---|---|
| M1 无法接近相同配置下的 RPent/Harness 基线 | 复现条件或环境不一致 | 报告差异，不进入增量结论 |
| M2 相对原终止谓词无显著改善 | 原终止机制已足够 | 删除复杂校验，保留协议复现基线 |
| M3 仅在引导随机种子有效 | 记忆主要实现轨迹复现 | 不支持跨随机种子泛化声明 |
| LLM 不优于固定状态机 | 收益来自 Harness 而非 LLM 规划器 | 采用固定状态机作为默认规划器 |
| P0 有效而 P1 失效 | 方法依赖特权状态 | 结论限定于特权感知 |
| 延迟感知模式净收益为负 | 推理等待或动作过期抵消成功率增益 | 降低调用频率或收缩系统结构 |
| 学习式校验器不优于规则 | 学习复杂度缺少闭环收益 | 保留规则方法 |

上述条件用于限定方法的适用范围，并与主要研究问题一一对应。

## 8. 结论

VLA 已经提供了可复用的局部视觉—语言—动作能力，但多阶段任务还要求任务状态、目标重绑定、结果校验、失败恢复和多时间尺度执行。现有研究支持模型内层级推理和模型外 Harness 两条路线；在单卡、公开数据和冻结检查点约束下，外部执行框架更适合作为本课题的研究对象。

本研究不预设 LLM 高层智能体、学习式校验器或结构化记忆必然优于固定规则，而是通过协议复现基线、逐项增量和延迟感知评测确定其实际贡献。预期结果是一套能够说明“哪些长程问题可以由外部执行框架解决、以何种资源代价解决”的实验结论。
