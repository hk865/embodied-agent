# 具身 Agent 论文总表

> 本页是人工策展索引，不是按关键词抓取的链接堆。机器可读版本见 [`../data/papers.csv`](../data/papers.csv)。
>
> 选择原则：论文必须至少回答规划、工具、反馈、记忆、恢复、VLA 执行或 Agent 评测中的一个问题。纯 VLA 架构只保留能作为执行器 baseline 的代表作。

## 1. 优先级说明

| 优先级 | 含义 |
|---|---|
| P0 | 与“冻结 VLA + Agent/Harness + Verifier + Memory”直接相关，必须精读 |

## 6. 按研究问题找论文

| 如果你要研究…… | 首读 | 用作概念对照 | 主要评测 |
|---|---|---|---|
| 技能选择与工具调用 | SayCan、Code as Policies | VLAs-as-Tools、Cortex | 计划合法率、工具选择准确率、成功率 |
| 闭环反馈与失败恢复 | Inner Monologue、Harness VLA | HELM、Goal2Skill | 失败发现延迟、恢复率、冗余动作 |
| 结构化记忆 | RMBench、HELM | MemoryVLA、Reflective VLA | 留出 seed 成功率、重复失败率、记忆成本 |
| 冻结 VLA 的外部增强 | Harness VLA | HELM、Goal2Skill | LIBERO-Pro、RoboCasa365、RoboTwin |
| 规划—执行对齐 | Cortex、VLAs-as-Tools | Steerable VLA、ReKep、HiRoC | 计划可执行率、调用忠实度、重规划次数 |
| 模型内 Agentic VLA | π0.5、OneTwoVLA | ECoT、MemoryVLA、Reflective VLA | 长程任务、推理触发、训练/推理成本 |
| 低资源实现 | OpenVLA / 匹配任务的小型 VLA（SmolVLA、TurboVLA） | Diffusion Policy、Octo | 显存、p95 延迟、闭环成功率 |

## 7. 推荐阅读顺序

### 7.1 一周建立全局观

1. SayCan：理解“语言合理”与“机器人可行”必须共同打分；
2. Inner Monologue：理解环境反馈如何改变计划；
3. OpenVLA 与 π0.5：理解局部执行器和 action chunk；
4. Goal2Skill 与 VLAs-as-Tools：理解双系统和工具接口；
5. HELM 与 Harness VLA：理解记忆、校验、恢复与冻结策略；
6. LIBERO-Pro 与 RMBench：理解为什么标准成功率不够。

### 7.2 围绕当前课题精读

精读顺序建议为 Harness VLA → HELM → Goal2Skill → VLAs-as-Tools → Cortex → HiRoC。每读一篇都填写：

- 它相对什么 baseline 增加了哪些模块；
- 是否一次改变了多个因素；
- 使用何种特权状态；
- 世界是否暂停等待推理；
- 代码、检查点和 benchmark 是否可得；
- 哪一项能在本地固定 VLA 后端后单变量复现。

## 8. 当前收集缺口

后续优先补充以下证据，而不是继续无差别增加 VLA 模型：

- Harness / learned verifier 的同协议独立复现；
- 持续世界中的 Agent 延迟与动作过期测量；
- 真机失败恢复与安全边界；
- 记忆引导成本、写入泄漏和跨 seed 泛化；
- 固定 FSM 与 LLM Planner 在同工具、同预算下的系统比较；
- 规则 Verifier、轻量 learned verifier 与完整世界模型的成本—收益曲线。
