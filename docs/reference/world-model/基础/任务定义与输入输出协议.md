# 任务定义与输入输出协议

## 1. Task Card 必填字段

| 字段 | 示例 | 为什么不可省略 |
|---|---|---|
| 场景和 embodiment | Franka 台面抓取 / 城市驾驶 | 决定动作、传感器和物理范围 |
| 消费者 | 数据引擎 / MPC / VLA 辅助损失 | 决定输出精度与实时性 |
| 观测 `o` | 多视角 RGB-D、proprio、语言 | 决定部分可观测性 |
| 状态 `z` | video latent、对象槽、occupancy | 决定什么必须保持 |
| 动作 `a` | TCP delta、扭矩、键鼠、车辆曲率 | 决定因果接口 |
| 时间尺度 | 10Hz、4 帧 token、4 秒 horizon | 决定窗口与误差累积 |
| 输出 | future video / state / reward / action | 决定损失和评测 |
| 风险约束 | 碰撞、失败、误报、时延 | 决定 verifier 与部署接口 |

## 2. 五种最常用任务

| 任务 | 输入 | 输出 | 是否要求动作 |
|---|---|---|---|
| 观察预测 | `o≤t,c` | `o>t` 或 `z>t` | 否 |
| 正向动力学 | `z_t,a_t,c` | `z_t+1`、`o_t+1` | 是 |
| 逆动力学 | `z_t,z_t+1` | `a_t` | 可选 |
| 目标条件规划 | `z_t,g` | `a_t:t+H` 或候选分数 | 通常是 |
| 联合 WAM | `o≤t,a<t,c` | future world + action | 是 |

## 4. 动作接口规范

动作应显式记录：参考坐标系、单位、采样率、延迟、夹爪/接触状态、归一化统计、chunk 长度和安全裁剪。不能把不同机器人动作直接拼接为一串浮点数，再把跨 embodiment 的失败归因于模型。

推荐在训练前做一次动作 round-trip：`raw → normalized/tokenized → decoded → controller`，报告位置、旋转、夹爪和时延误差。

## 5. 最小可复现任务

**动作条件视觉预测**：输入 4 帧 RGB、未来 8 步 TCP delta、任务文本；输出 8 帧 latent 或 RGB；对照为“同 Base、去动作条件”与“动作打乱”。

伪代码：

```python
batch = sample_window(history=4, future=8, aligned_action=True)
z = encoder(batch.obs_history)
z_hat = dynamics.rollout(z, batch.action_future, batch.text)
loss = prediction_loss(z_hat, encoder(batch.obs_future))
loss.backward()
```

## 6. 失败模式

- 相机运动被误学成物体运动；
- action 与图像错一帧，模型学到错误因果；
- 参考坐标系混用，离线误差低而真实控制失败；
- 只用成功轨迹，模型不会预测失败和恢复。
