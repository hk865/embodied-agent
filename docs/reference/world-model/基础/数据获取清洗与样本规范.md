# 数据获取清洗与样本规范

## 1. 数据源不是一锅混

| 来源 | 提供什么 | 主要缺口 | 合适用途 |
|---|---|---|---|
| 互联网视频 | 视觉、语义、常识、动作外观 | 无精确动作和标定 | 视频/JEPA Base 预训练 |
| 机器人轨迹 | 动作、proprio、接触、失败 | 规模小、设备异构 | 动作对齐与闭环后训练 |
| 自动驾驶日志 | 多传感器、长时动态体 | 稀有事故与强标注少 | 驾驶预测和场景生成 |
| 游戏/物理引擎 | 真值状态、碰撞、反事实 | sim-to-real gap | 因果评测和状态监督 |
| NeRF/3DGS 重建 | 外观、相机和空间一致性 | 不含新动力学 | 多视角、重访和数字孪生 |
| 生成数据 | 可控长尾、天气、布局 | 生成偏差会回灌 | 数据增广，不能替代真值评测 |

## 2. 原始数据到训练 shard 的流程

1. 固化数据许可、来源、版本和隐私策略。
2. 解码并保留原始时间戳，不先强行重采样。
3. 标定相机内外参、机器人/车辆坐标和传感器延迟。
4. 估计或读取动作执行时刻，建立 action-to-observation 对齐。
5. 删除损坏文件、剪辑跳变、黑帧、重复片段和明显不同步样本。
6. 标记静态、运动、接触、遮挡、失败、重访和长尾事件。
7. 统一单位、坐标系、动作类型、文本模板和 tokenization。
8. 以固定窗口、事件窗口或混合窗口切片；保留 episode 边界。
9. 按场景、实例、路线、操作者或时间段切分，防止近重复泄漏。
10. 写出 shard、manifest、统计量、质量标签和可追溯 sample id。

## 3. 三种窗口策略

| 方式 | 优点 | 风险 | 推荐场景 |
|---|---|---|---|
| 固定窗口 | 简单、吞吐稳定 | 接触与稀有事件被稀释 | 视频预训练 |
| 事件窗口 | 对齐因果变化 | 采样偏差、实现复杂 | 机器人操作、驾驶风险 |
| 混合采样 | 兼顾背景和关键变化 | 需要明确配比 | 通用具身后训练 |

## 4. 数据质量门槛

对每段样本记录 `sync_ms`、相机/动作有效率、运动幅度、曝光/模糊、标定版本、场景 id、对象 id、事件标签和来源权重。质量分不是只用于删除，也应作为采样权重或损失 mask。

## 5. 3DGS 与合成数据的正确位置

3DGS 可以把真实采集转为多视角可渲染空间，适合产生视角扰动、背景变化和重访样本；它不是接触动力学标签。若用于机器人训练，需额外提供 collider、对象位姿、材料/摩擦近似、关节约束或真实交互校准。

## 6. 最小数据卡

```yaml
dataset: tabletop-mix-v1
modalities: [rgb, depth, proprio, action, language]
rate_hz: 10
action_frame: tcp_base
source_mix: {web_video: 0.6, robot: 0.3, sim: 0.1}
split_key: scene_id + object_instance
failure_coverage: 18%
known_gaps: [deformable_objects, force_torque]
```

## 7. 失败模式与检查

- [ ] 训练集和测试集不存在同一场景的近重复片段。
- [ ] 动作与未来观测的 offset 经过可视化确认。
- [ ] 成功、失败、恢复和无效动作的比例被报告。
- [ ] 生成数据不作为唯一物理正确性评测来源。
- [ ] 每个结果可追到原始 episode 与数据版本。
