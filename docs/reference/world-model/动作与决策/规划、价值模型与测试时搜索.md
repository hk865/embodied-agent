# 规划、价值模型与测试时搜索

## 1. 任务与资格

世界模型的决策价值通常通过：生成未来、估计 reward/value/constraint、在候选动作中选择最优。

\[
a_{t:t+H}^*=\arg\max_a\mathbb E_{p_\theta}\left[\sum_{k=0}^{H}\gamma^k r(\hat z_{t+k},a_{t+k})-\beta\,\mathrm{risk}(\hat z_{t+k})\right]
\]

这条路线不是另一个表示空间，而是“如何消费世界模型输出”的动作轴末端。

## 2. 输入输出与数据

输入为当前 belief/state、目标、候选动作分布、世界模型和可选 value/verifier；输出为动作 chunk 或高层子目标。训练价值模型时需要可靠 reward、成功标签或偏好数据；安全约束需要正反例与不确定性处理。

## 3. 最小 Baseline

| 方法 | 最小实现 | 对照 |
|---|---|---|
| 直接策略 | `π(a|z,c)` | 无模型基线 |
| random shooting | N 个候选 + world rollout | 同 wall-clock 随机/单样本 |
| CEM / MPPI | 分布迭代采样 | 同候选预算 random shooting |
| beam search | token action 候选 | greedy decoding |
| value rerank | world futures + V/Q/verifier | 无 value / oracle value |

## 4. 训练目标与损失

规划器可以没有单独可训练参数，但它消费的 reward、value、risk 和 proposal 都必须有训练或标定目标：

\[
\mathcal L_{plan}=\lambda_v\|V_\rho(z_t)-G_t\|^2+\lambda_q\mathcal L_Q+\lambda_{risk}\mathcal L_{risk}+\lambda_{bc}\mathcal L_{proposal}
\]

`G_t` 可以来自真实回报、成功标签或经验证的偏好；风险 head 必须使用失败、近失败和安全边界样本，而不是把“未发生碰撞”简单视为安全。value/score 的离线准确性不足以证明规划有效，仍需与同预算的直接策略做闭环对照。

## 5. 训练与推理

规划常见伪代码：

```python
candidates = proposal.sample(n=N, horizon=H)
futures = world.rollout(current_state, candidates)
scores = value(futures) - risk_verifier(futures)
action = candidates[scores.argmax()][0]
execute(action)
```

需要做 receding horizon：每执行少量动作就重新观测和规划；开环长计划会放大模型误差。

## 6. 评测

- 模型准确性：候选未来与真实未来的排序是否一致；
- 规划收益：task success、return、regret、sample efficiency；
- 安全：碰撞/越界/失败 recall 与 false positive；
- 资源：candidate 数、horizon、GPU 时延、控制频率；
- 稳健性：模型错误、OOD、感知丢失、对抗 exploit。

## 7. 测试时计算的正确报告方式

报告 `N × H × decoder cost`、实际控制周期、缓存策略、温度/beam 宽度、停止条件。只报“多采样更好”不足以说明模型有效，必须与相同总推理预算的直接 policy 和随机候选比较。

## 8. 失败模式

- 策略在模型漏洞处得到虚假高分（model exploitation）；
- 模型对罕见失败过度乐观；
- 视频 rollout 过慢，动作已经过时；
- value 学到训练场景 shortcut，排序无法外推。

缓解手段包括 ensemble/uncertainty、conservative objective、真实数据校正、短 horizon 重规划、rule-based safety shield 和显式失败数据。
