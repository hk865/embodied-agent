# 压缩、实时推理与部署

## 1. 部署目标先于优化方法

报告目标控制频率、端到端时延、显存/功耗、网络依赖、失联退化、安全 fallback 和可解释日志。没有这些约束，“世界模型能用于机器人”只是离线声明。

## 2. 常见部署分层

| 层 | 频率 | 推荐职责 |
|---|---|---|
| 安全/低层控制 | 100—1000Hz | 力控、限位、碰撞、急停 |
| 反射策略 | 10—50Hz | 局部视觉伺服、action chunk |
| 世界模型/规划 | 1—10Hz 或事件触发 | 高层 rollout、风险评估、重规划 |
| 云端/离线 | 非实时 | 长 rollout、数据生成、模型分析 |

不是所有 WM 都需要高频在线运行；更实际的模式是事件触发的“慢思考”与快速控制器协作。

## 3. 优化工具箱

- 训练时丰富、推理时轻量：关闭 video decoder、只保留 latent dynamics/value；
- distillation：大世界模型教师 → 小规划/策略学生；
- tokenizer/latent compression：降低时空 token；
- KV cache、SSM、稀疏/检索记忆：控制长序列成本；
- quantization、batching、编译与异步 pipeline；
- adaptive compute：仅在不确定、高风险、长时任务时调用多样本搜索。

## 4. 最小部署接口

```python
decision = world_service.evaluate(
    observation=obs,
    candidate_actions=proposal(obs),
    deadline_ms=80,
    return_uncertainty=True,
)
action = safety_filter(decision.best_action, decision.risk)
controller.execute(action)
```

接口应返回 action、score、risk/uncertainty、模型版本和超时状态，而不是只返回一段视频。

## 5. 评测

同时报告 p50/p95/p99 时延、GPU/内存、实际执行频率、超时率、fallback 触发率、任务成功和安全事件。离线吞吐不能替代在线控制时延。

## 6. 失败模式

- 蒸馏后只保留策略表面行为，丢失预测能力；
- 量化改变 action token 分布，导致小幅控制震荡；
- 生成式 decoder 占满预算，导致重规划过晚；
- 缓存或记忆过期，将旧世界当成当前世界。
