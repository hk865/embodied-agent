# 离散动作 Token：从连续控制量到自回归序列

> 本文讨论动作如何被改写为离散符号、送入语言模型并重新解码为物理命令。重点不是“离散动作是否先进”，而是量化器、序列布局、词表、训练目标和执行协议如何共同决定精度、延迟与可迁移性。

## 1. 学习目标

读完本文，应能够：

- 从一份 [Action Contract](../基础/任务定义与输入输出协议.md) 构造可逆的动作 tokenizer；
- 区分逐维分箱、轨迹压缩 tokenizer 和学习式 tokenizer；
- 解释 RT-1、RT-2、OpenVLA 与 FAST 在同一模块上的差异；
- 设计量化误差、序列长度、推理延迟和闭环性能的受控实验；
- 判断一个“动作 token 改进”究竟改变了表示、模型容量还是执行协议。

## 2. 理论对象：Tokenizer 是动作接口的一部分

设动作块为

\[
\mathbf A_t=[\mathbf a_t,\ldots,\mathbf a_{t+H_{pred}-1}]
\in\mathbb R^{H_{pred}\times D_a}.
\]

离散路线引入编码器与解码器：

\[
\mathbf z=T_{enc}(\mathbf A_t;\eta),\qquad
\hat{\mathbf A}_t=T_{dec}(\mathbf z;\eta),
\]

其中 \(\eta\) 包含坐标语义、归一化统计、分箱端点、词表和序列布局。策略学习的是

\[
p_\theta(\mathbf z\mid h_t)
=\prod_{j=1}^{N_z}p_\theta(z_j\mid h_t,z_{<j}),
\]

而控制器消费的是 \(T_{dec}(\mathbf z)\)。因此 tokenizer 不是外围格式转换：它决定目标分布、序列长度、量化误差以及一次模型查询要进行多少次自回归解码。

### 2.1 最小正确性条件

一个可用 tokenizer 至少满足四个条件：

1. **语义闭合**：编码前后的坐标系、单位、绝对/增量语义不变；
2. **范围闭合**：训练、评测和部署使用同一套统计与裁剪规则；
3. **次序闭合**：维度顺序、时间顺序和特殊命令的位置固定；
4. **执行闭合**：解码结果能经过本体 adapter 与安全层进入控制器。

只比较 token accuracy 而不验证这四点，无法区分“模型不会预测”和“动作被错误解码”。

## 3. 逐维分箱：RT 系与 OpenVLA 的共同骨架

### 3.1 归一化、量化和反量化

对动作维 \(d\)，先根据训练集确定有效区间 \([l_d,u_d]\)，再裁剪和归一化：

\[
x_d=\operatorname{clip}\!\left(
\frac{a_d-l_d}{u_d-l_d},0,1\right).
\]

使用 \(K\) 个 bin 时，可写成

\[
q_d=\min(K-1,\lfloor Kx_d\rfloor),
\qquad
\hat a_d=l_d+\frac{q_d+0.5}{K}(u_d-l_d).
\]

若落在区间内且使用 bin center 解码，单维最坏量化误差不超过半个 bin：

\[
|a_d-\hat a_d|\le \frac{u_d-l_d}{2K}.
\]

这个界只描述 tokenizer 的静态误差，不包含坐标转换误差、动作延迟和闭环误差。旋转维与平移维的物理影响也不同，不能把各维 token accuracy 简单平均后视为控制精度。

### 3.2 均匀端点与分位数端点

| 端点 | 机制 | 收益 | 风险 |
|---|---|---|---|
| 物理/人工范围 | 使用 Action Contract 中的固定上下界 | 跨数据集语义稳定 | 范围过宽会浪费分辨率，过窄会频繁裁剪 |
| 训练集 min/max | 覆盖观测到的极值 | 实现直接 | 单个离群值即可拉宽全部 bin |
| 分位数范围 | 用第 1/99 或其他分位数作端点 | 对离群动作更稳健 | 是否裁剪取决于实现；统计与区间外比例必须保存 |
| 每数据集统计 | 各数据集独立量化 | 充分利用各自动态范围 | 相同 token 在不同数据集表示不同物理量 |

OpenVLA 的 EEF_POS 数据合同对前 6 个相对末端动作维使用训练集第 1/99 分位数并裁剪到 \([-1,1]\)；绝对夹爪维绕过这一步，先按独立夹爪语义整理。随后 7 个归一化动作值都通过共享的 256-way 动作 tokenizer。其收益不是“256 比别的数字好”，而是让连续动作进入 LLM 输出接口；复现时不能把夹爪误写成与 EEF delta 相同的分位数连续量。

## 4. 模块数据流

```mermaid
flowchart LR
    A["物理动作块<br/>H_pred × D_a"] --> C["坐标与语义统一<br/>frame · unit · delta"]
    C --> N["裁剪与归一化<br/>统计随 checkpoint 保存"]
    N --> Q["量化 / 轨迹压缩"]
    Q --> L["序列布局<br/>时间 × 维度 × 命令"]
    L --> V["映射到动作词表"]
    V --> M["自回归 Transformer<br/>next-token CE"]
    M --> D["约束解码"]
    D --> U["反量化 / 逆变换"]
    U --> G["本体 Adapter + 安全门控"]
    G --> R(["机器人控制器"])
```

读图时应把 `Q/L/V` 看作三个不同模块：量化器决定信息损失，序列布局决定条件分解，词表映射决定怎样复用 VLM 输出层。三者同时变化时，实验不能只归因于“动作 token”。

## 5. 真实模型怎样实例化这条路线

| 模型 | 动作对象 | Tokenizer | 序列与目标 | 工程后果 |
|---|---|---|---|---|
| RT-1 | 11 维：手臂 7、底盘 3、模式 1 | 连续维均匀 256-bin | decoder-only Transformer 预测动作 token | 约 35M，6 帧历史，经 TokenLearner 压缩；约 3 Hz 闭环 |
| RT-2 | 6-DoF EEF 增量、夹爪、终止 | 连续维均匀 256-bin | 8 个整数式动作符号；动作段 next-token CE | PaLI-X 复用整数 token，PaLM-E 覆写低频词；55B 约 1–3 Hz |
| OpenVLA | 6 维 EEF 增量 + 1 维绝对夹爪 | 前 6 维 q01/q99 + clip；夹爪独立语义；共同进入 256-way tokenizer | 7 个动作 token；只在动作段计算 CE | 复用 Llama 词表末端动作 token；7B 主干串行生成限制刷新率 |
| FAST / π0-FAST | 1 秒连续动作块 | 分位数归一化 → DCT → 系数量化 → BPE | 约 30 token/臂/chunk，再做 next-token CE | 提升高频序列的信息密度，但 π0-FAST 推理仍需完整语言主干自回归 |

这些数字来自论文/官方资料中的不同系统协议，不能据此直接排名。RT-1 的 3 Hz 是闭环策略口径，RT-2/OpenVLA 的速度受远程服务和硬件影响，π0-FAST 的 chunk 延迟又与动作块长度绑定。

### 5.1 RT-1：动作分类而非语言词表复用

RT-1 已经具备“动作离散后由 Transformer 预测”的骨架，但它不是互联网 VLM。6 帧 300×300 图像经过 EfficientNet-B3、FiLM 与 TokenLearner，从每帧 81 个视觉 token 压到 8 个；Transformer 再预测 11 个 256-way 动作分类。它说明离散目标可直接用于闭环策略，但不能单独证明网络视觉语言知识的迁移。

### 5.2 RT-2：把动作塞进既有 VLM 符号系统

RT-2 的创新点在于最大程度复用 VLM：图像和指令被包装为 VQA 输入，动作被写成固定顺序的整数符号串。PaLI-X 已为 0–999 的整数保留独立 token；PaLM-E 版本则将最低频的 256 个词表项重新赋予动作含义。推理必须约束输出词表，否则生成一个语言词而不是合法动作就无法执行。

### 5.3 OpenVLA：开放的分位数量化基线

OpenVLA 使用 DINOv2 与 SigLIP 双视觉编码，经 2 层投影器接入 Llama 2 7B。动作侧每个时间步输出 7 个 token。训练时只有动作 token 进入损失；部署时根据数据集 key 对前 6 个 EEF 维读取对应统计做反量化，并按独立合同恢复夹爪命令。于是 checkpoint、normalization metadata 与 gripper contract 是不可拆分的部署资产。

### 5.4 FAST：从“量化单个值”转为“压缩整段轨迹”

逐步逐维量化长度近似为

\[
N_{naive}=H_{pred}D_a.
\]

当控制频率升高，相邻动作高度相关，序列会变长但每个 token 的新增信息变少。FAST 先对每个动作维的时间序列做 DCT：

\[
\mathbf C_d=\operatorname{DCT}(\mathbf A_{:,d}),
\qquad
\bar{\mathbf C}_d=\operatorname{round}(\gamma\mathbf C_d),
\]

再按低频优先顺序展平并用 BPE 合并稀疏、重复的系数模式。解码按 BPE 解码、除以 \(\gamma\)、逆 DCT 和反归一化逆序进行。论文单数据集实验采用 \(\gamma=10\)、BPE 词表 1024；FAST+ 的 BPE 词表由约 100 万条一秒真实动作块训练。上述值是论文配方，不是所有机器人都应照抄的常数。

## 6. 训练路径与推理路径

| 环节 | 训练 | 推理 |
|---|---|---|
| 动作来源 | 数据中的真实动作块 | 无真实动作；模型生成 token |
| 量化统计 | 由训练集拟合并冻结 | 从 checkpoint metadata 加载 |
| 序列 | teacher-forced target | 自回归逐 token 生成 |
| 合法词表 | loss mask 只覆盖动作目标 | constrained decoding 只允许合法动作/终止符 |
| 长度 | 可由固定维数或 EOS 决定 | 影响首动作延迟与异常输出处理 |
| 输出 | CE、token accuracy、checkpoint | 连续动作、队列状态和解码告警 |

训练 token accuracy 高只说明离散目标在训练分布上可预测。它不包含反量化误差、动作之间的物理耦合，也不暴露 rollout 后的状态偏移。

## 7. 工程实现应固定的契约

### 7.1 Tokenizer manifest

| 字段 | 示例 | 作用 |
|---|---|---|
| `action_semantics` | EEF delta + gripper | 防止把 token 映射到错误控制接口 |
| `dimension_order` | x,y,z,rx,ry,rz,g | 确保编码与解码次序一致 |
| `frame/unit` | base frame；m/rad | 固定物理解释 |
| `normalization` | per-dataset q01/q99 | 绑定统计来源和版本 |
| `bins/vocab` | 256 / action token ids | 固定量化与词表映射 |
| `layout` | time-major 或 dimension-major | 决定自回归因子分解 |
| `H_pred/H_exec` | 预测块与执行段 | 连接 tokenizer 与在线调度 |
| `invalid_mask` | 缺失自由度与 padding | 避免将填充值作为监督或动作 |
| `fallback` | EOS 缺失、越界、NaN | 定义拒绝、重试或安全停止 |

### 7.2 Round-trip 验收

上线前至少验证：

1. **数值 round-trip**：对训练分布和边界动作计算 \(a\to z\to\hat a\) 误差；
2. **单轴脉冲**：每次只改变一个维度，确认方向、单位和维度顺序；
3. **尾部分布**：统计裁剪率，避免大量动作堆积在首尾 bin；
4. **词表约束**：验证生成过程不会产生自然语言 token 或未知动作符号；
5. **metadata 错配测试**：刻意替换数据集统计，确保系统能检测而不是静默执行。

## 8. 怎样选择离散路线

| 条件 | 逐维分箱更合适 | 轨迹 tokenizer 更合适 | 需要谨慎 |
|---|---|---|---|
| 动作频率 | 较低、单步变化有信息 | 高频、相邻时间步冗余大 | 高频逐步 token 会造成长序列 |
| 动作块 | 单步或很短 | 一秒左右连续块 | 变长后自回归首动作延迟上升 |
| 复用 VLM | 希望最小改动输出层 | 希望仍用 next-token 但提高信息密度 | 覆写词表可能影响原语言能力 |
| 多峰性 | 分类分布可表达每个 token 的不确定性 | 可表达轨迹模式组合 | 独立逐维 token 不自动建模物理耦合 |
| 部署 | LLM 推理栈成熟 | 可用同一 LLM 加速工具 | 串行生成长度仍是硬约束 |

## 9. 可归因的实验设计

研究 tokenizer 时，至少拆成三组实验。

### 9.1 表示保真度

- 固定真实动作，不训练策略；扫描 bin 数、分位数端点、\(\gamma\) 或词表大小；
- 报告每维 MAE、旋转误差、轨迹 jerk、裁剪率和 token/chunk；
- 用控制器回放解码动作，检查可执行性，而不只画重建曲线。

### 9.2 学习难度

- 固定 Base、数据窗口、训练步数和动作合同；
- 比较训练 CE、验证 CE、序列长度、有效 token 熵和收敛速度；
- 防止只因一种 tokenizer 使用更多计算或更大词表而宣称表示更优。

### 9.3 闭环与系统

- 固定观测、控制器和评测 seed；
- 报告成功率、首动作延迟、chunk 生成延迟、策略刷新率、动作采样率和安全拒绝率；
- 单独改变 \(H_{exec}\)，区分 tokenizer 收益与减少重规划次数带来的吞吐收益。

## 10. 常见失败及定位

| 现象 | 优先检查 | 机制 |
|---|---|---|
| 动作总在边界 | 分位数统计、单位和裁剪率 | 运行分布超出训练量化区间 |
| 单轴方向错误 | dimension order、frame、旋转约定 | token 正确但物理解释错位 |
| token accuracy 高、闭环失败 | 解码误差、状态偏移、控制器 | teacher forcing 不等于闭环稳定 |
| 高频任务学成复制上一动作 | token 信息密度与序列自相关 | 朴素逐步分箱形成平凡预测目标 |
| 首动作延迟很高 | 生成 token 数与完整主干前向 | action chunk 摊薄执行成本但不消除自回归延迟 |
| 换数据集立即失效 | normalization/tokenizer metadata | 相同 token id 表示了不同物理范围 |

## 11. 检查点

给定一个 20 Hz、\(H_{pred}=20\)、\(D_a=7\) 的策略：

1. 朴素逐步逐维分箱需要多少动作 token？
2. 若只把 bin 从 256 增加到 512，能否解决时序冗余？为什么？
3. OpenVLA 与 π0-FAST 的比较中，除 tokenizer 外还需要固定哪些模块和训练预算？
4. 若动作生成吞吐为 100 chunk/s，能否直接称为 100 Hz 闭环控制？

答案锚点：分别检查 \(H_{pred}D_a\)、时间相关性、Base/数据/动作合同/序列长度/解码预算，以及 [任务协议中的频率区分](../基础/任务定义与输入输出协议.md#6-时间协议三个频率和两个-horizon)。
