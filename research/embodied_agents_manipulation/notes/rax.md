## 探索最终要留下可执行的决策规则

RAX 的中心是扩大在线探索：冻结 coding agent 在预算内亲自尝试，记录原因、改写程序，并把有效流程整理成可重新感知、规划和执行的程序。模型参数不更新，变化保存在工作区笔记、代码和验证过的技能库。（§3）

## 用空气炸锅任务理解它

论文真机例子中，Agent 将 RGB-D 转成机器人坐标系点云，拟合设备轴线、把手方向和抽屉运动结构；用机器人模型与 IK 检查接近/拉出姿态，然后分段执行并再次观察。成功后，它把这些测量与决策步骤写进程序，下一布局重新测量，而不是简单回放旧末端轨迹。

程序保留前提检查和效果验证；几何估计或规划不可信时抛出 `Unsure()`，在允许 Agent 参与的运行模式下把控制权交回 Agent。低层控制、驱动和约束执行位于隔离后端，前端生成的程序不能任意改写这些设施。（§3.2–3.4、§4）

## 两个容易混淆的“自动”

Fully automated program 评估把提交程序放到新场景，没有主 coding agent、临场编辑或重试，结果不回流探索；另一种模式保留 Agent-in-the-loop。前者不等于没有任何模型调用：附录 C.1 允许 Agent 和程序调用 Gemini 3.8 Flash，探索与评估共享每 session 的 10 美元辅助模型预算。（附录 C.1–C.2）

示范条件必须按基准拆开：RoboDojo、BEHAVIOR-1K、DexJoCo、LIBERO-Pro 的相关主结果没有专家动作轨迹，部分条件仍可给目标图像或视觉参考；**HumanoidArena 主结果每任务给探索 Agent 三条含动作的遥操作示范**，程序可复用其中的运动片段。§5.3.4 的 RAX⋆ 才去掉示范中的动作，而且增加了探索预算，因此不能把该消融当成主结果的同预算替代。真机展示使用零示范，但仍需要操作员 arming、复位或 `request_operator`，不能描述成无人照管的终身学习。（§5.2.3、§5.3.4、附录 G）

## 证据与局限

论文覆盖多个仿真平台和不同本体，并展示真实精细、关节物体、软体及长程任务。不同基准可能使用成功率或部分得分；本文不将其混合平均 headline 解释为统一操作成功率。更多探索改善性能同时消耗交互和计算，开发成本不能从部署速度中消失。

对 RPent 最可取的是“成功轨迹→可重算程序→前提与证据”的路线，以及冻结后在留出初态评估。可以先将稳定任务段整理成有限程序，遇到预期外情况再交回 Agent，比较总时间和失败率；这只是后续研究选项，尚未实施。
